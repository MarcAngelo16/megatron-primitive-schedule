# CAL Evaluation Analysis

`scripts/analyze_cal_results.py` turns manifest-backed CAL runner outputs into
the compact figures, table fragments, and provenance summaries used for paper
evaluation. It is intentionally deterministic and conservative: incompatible
rows are reported in preflight outputs before aggregation, and missing oracle or
convergence data is never fabricated.

## Inputs

The analyzer reads:

- a JSONL manifest generated by `scripts/generate_cal_manifest.py`
- a runner result root containing each row's `output_json`
- canonical result JSON files, either directly or wrapped by the manifest runner
- optional `incumbent_trace` arrays already serialized in canonical results
- activation diagnostics already serialized in canonical results

It reuses `cal_manifest.check_result_against_manifest` for compatibility checks.
Those checks cover manifest hash/run id, canonical method and method contract,
schema and policy versions, git policy, controlled problem fields, cost and
communication settings, activation model and cap fields, time limit, seed, and
solver thread count. The analyzer additionally verifies the serialized cyclic
`stage_to_worker_mapping` against the manifest row.

## Commands

Smoke analysis:

```bash
python3 scripts/analyze_cal_results.py \
  --manifest manifests/cal_smoke.jsonl \
  --results-root results/cal_smoke \
  --output-dir results/cal_smoke_analysis \
  --mode both \
  --include-groups smoke \
  --strict \
  --format pdf,png,csv,json,tex
```

Production analysis, after a production run has completed:

```bash
python3 scripts/analyze_cal_results.py \
  --manifest manifests/cal_main.jsonl \
  --results-root results/cal_main \
  --output-dir results/cal_main_analysis \
  --mode both \
  --include-groups main \
  --strict \
  --format pdf,png,csv,json,tex
```

Uncapped-only 1F1B big-profile analysis, after that opt-in production run has
completed:

```bash
python3 scripts/analyze_cal_results.py \
  --manifest manifests/cal_main_big_5min_1f1b_uncapped.jsonl \
  --results-root results/cal_main_big_5min_1f1b_uncapped \
  --output-dir results/cal_main_big_5min_1f1b_uncapped_analysis \
  --mode uncapped \
  --include-groups main_big_5min_1f1b_uncapped \
  --strict \
  --emit-utilization-vs-batch \
  --format pdf,png,csv,json,tex
```

To produce only the simulated-utilization figure and backing data, keep
`--emit-utilization-vs-batch` and request `--format pdf,csv,json`.

For the all-N/W paper-style utilization figure, use the uncapped-only big
profile and pass `--utilization-panel-n-over-w all`. This aggregates over
`N/W in {1, 2, 4}`, uses `B/W in {0.5, 1, 2, 4, 8}` on a log2 x-axis, and plots
only `BFS`, `Partition-only`, `Schedule-only`, and `SlackPipe`:

```bash
python3 scripts/analyze_cal_results.py \
  --manifest results/cal_main_big_5min_1f1b_uncapped/manifests/cal_main_big_5min_1f1b_uncapped.jsonl \
  --results-root results/cal_main_big_5min_1f1b_uncapped/results \
  --output-dir results/cal_main_big_5min_1f1b_uncapped/analysis \
  --mode uncapped \
  --include-groups main_big_5min_1f1b_uncapped \
  --strict \
  --emit-utilization-vs-batch \
  --utilization-panel-n-over-w all \
  --format pdf,csv,json,tex
```

Use `--allow-unavailable` when analyzing an OR-Tools-disabled smoke result set
for diagnostics. Use `--no-strict` only for incomplete exploratory data; paper
claims should come from strict runs.

## Row Classifications

Preflight rows can carry multiple classes:

- `valid_for_uncapped`
- `valid_for_equal_memory`
- `deterministic_baseline_valid`
- `unavailable`
- `invalid_result`
- `failed_process`
- `missing_result`
- `schema_mismatch`
- `manifest_mismatch`
- `method_contract_mismatch`
- `cap_ineligible`
- `validation_failed`
- `fallback_used`
- `not_optimal_but_feasible`
- `oracle_unproven`

Strict analysis fails on missing, invalid, schema/manifest/contract mismatch,
failed process, validation failure, and cap-ineligible rows. `unavailable` rows
also fail strict analysis unless `--allow-unavailable` is supplied.

Strict analysis also fails protocol guard checks when selected rows mix manifest
hashes, git commits, method contract hashes for the same method, budget policy
versions, evaluation method versions, validation versions, activation analysis
versions, or activation cap formulation versions.

## Aggregation

A workload key contains `B`, `N`, `W`, `L`, mapping type, serialized stage-worker
mapping, forward/backward cost ratios, communication profile and ticks,
activation model, activation cap mode, cap vector/hash, and cap enforcement
status. Rows with different controlled fields are never aggregated together.

For each workload, `uniform-breadth-first` is the default normalization
baseline. To normalize against the interleaved deterministic baseline instead,
pass `--normalization-baseline uniform-interleaved-1f1b`.
Normalized makespan is:

```text
method_makespan / selected_baseline_makespan
```

Solver-backed seeds are aggregated within a workload/method first. The default
seed aggregate is the median; best and worst seed normalized values are also
serialized. The paper-level statistic is the geometric mean of workload-level
seed medians.

Figure A includes, in order:

1. the non-selected uniform baseline, when present
2. `partition-only-fixed-order`
3. `schedule-only-uniform`
4. `sequential-partition-then-schedule`
5. `alternating-partition-schedule`
6. `joint-unrestricted-no-overlap`

The selected normalization baseline appears as the 1.0 reference line, not as a
primary bar.

## Simulated Utilization

The optional utilization-vs-batch figure reports simulator utilization, not
hardware GPU utilization. It uses only validated uncapped rows. For each result,
the analyzer computes:

```text
useful_compute = B * L * (forward_cost_per_layer + backward_cost_per_layer)
utilization_percent = 100 * useful_compute / (W * makespan)
```

Under the controlled CAL cost model, `forward_cost_per_layer = 1` and
`backward_cost_per_layer = 2`, so `useful_compute = 3 * B * L`. Communication
delay and pipeline bubbles are not included in the numerator; they reduce the
reported utilization through the makespan denominator.

The default paper-style figure uses two panels, `moderate` and `heavy`
communication, filters to `N/W = 2`, and places `B/W` on the x-axis. Solver
seeds are first summarized by median within each workload/method. Workloads
with the same panel, method, and `B/W` are then aggregated by geometric mean
when all utilization values are positive. The plotted default omits
`sequential-partition-then-schedule` for readability, but the CSV and JSON
backing data retain it.

Useful options:

- `--emit-utilization-vs-batch`
- `--utilization-panel-n-over-w 2`
- `--utilization-panel-n-over-w all`
- `--utilization-communication-panels moderate,heavy`
- `--utilization-include-sequential false`
- `--utilization-normalize no`

## Equal Memory

Equal-memory aggregation includes only cap-eligible rows:

- deterministic fixed-order methods may use
  `deterministic_postconstruction_check`
- solver-backed methods must have `activation_cap_satisfied = true`
- solver-backed methods must record solver-side cap enforcement
- solver-backed methods must record added activation cap constraints
- `posthoc_only`, cap-violating, unavailable, and invalid rows are excluded

Uncapped activation ratios remain diagnostic. They are summarized separately so
makespan improvements that require extra retained activation memory are visible.

## Oracle Rules

Oracle rows are summarized only when the manifest includes the `oracle` profile.
An optimum is used only when the oracle row is proven optimal. If comparable
joint, partition-only, or alternating rows share the same workload key, the table
reports reach-optimum percentages and joint optimality gaps. Missing comparable
rows leave those fields `null` with comparable counts of zero.

If no oracle rows are analyzed, `oracle_status = unavailable`.

## Convergence

Convergence uses best-so-far makespan over wall-clock seconds from serialized
`incumbent_trace` data. Checkpoints are `0.1`, `1`, `10`, and `30` seconds,
filtered to the row's configured time limit. A run with no incumbent by a
checkpoint contributes to feasible fraction but not to the geometric mean until
a best-so-far value exists.

Convergence aggregation mirrors Figure A: median over seeds per
workload/method/checkpoint, then geometric mean across workloads.

## LaTeX

`table_cal_summary.tex` is a small table fragment only. It includes comments
defining geometric mean, equal-memory eligibility, and the proven-oracle
requirement. The analyzer does not edit paper TeX files.
